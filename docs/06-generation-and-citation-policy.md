# 06. Generation and Citation Policy

## Decision

The LLM is a language layer over selected evidence. It may rewrite a conversational query and explain retrieved provisions, but it cannot decide legal hierarchy, validity, citation identity, or corpus membership.

## Generator input

The generator receives only:

    original_question
    rewritten_question when used
    effective_at
    evidence units with immutable IDs
    validity summary
    response_policy_version

It does not receive an unrestricted graph connection, raw source collection, or retrieval tool.

## Structured response

The model returns a schema equivalent to:

    answer: string
    claims:
      - text: string
        citation_unit_ids: list of string
    warnings: list of string
    needs_clarification: boolean
    abstain: boolean
    confidence_label: high | medium | low

The server validates the schema. One repair attempt may remind the model of format; a second failure returns a safe evidence-only fallback or an error, never unvalidated prose.

## Grounding rules

The system prompt and verifier enforce that the model:

- uses only selected evidence;
- does not invent document IDs, penalties, dates, or citations;
- distinguishes a source statement from an explanatory inference;
- states material conditions and exceptions present in evidence;
- does not call an unknown validity status current;
- asks for missing vehicle, behavior, location, or time information when it changes the legal answer;
- abstains when evidence cannot support the answer.

User text and legal text are data, never instructions. Citation markers are generated by the server, not trusted from model output.

## Citation verification

A legal claim passes only when each cited unit:

1. exists;
2. belongs to the active snapshot;
3. was in the evidence sent to the generator;
4. supports the claim within its legal scope;
5. does not contradict the requested effective date.

If verification fails, the service may remove an unsupported claim, return a more limited answer, ask for clarification, or abstain. It never searches freely during repair.

## Answer modes

| Mode | Use when | Behavior |
|---|---|---|
| Direct answer | Evidence directly covers a clear question | State conclusion and citation |
| Conditional answer | Outcome depends on facts | State supported conditions and missing facts |
| Clarification | A decisive fact is absent | Ask the smallest useful question |
| Abstention | Evidence, validity, or scope is insufficient | Say what cannot be verified and show safe sources if available |
| Retrieval fallback | Generation provider fails | Return ranked sources and a clear warning |

## User disclaimer

The UI displays a concise permanent notice:

> Thông tin dùng để tra cứu theo data snapshot hiển thị và không thay thế tư vấn pháp lý chính thức. Hãy kiểm tra văn bản gốc trước khi quyết định hành động.

Warnings are prominent only when needed; a long disclaimer is not inserted into every answer.

## Prompt governance

Each prompt artifact records name, version, intended model, input/output schema, golden cases, and change reason. Any prompt change reruns cases for exact citation, temporal validity, ambiguity, out-of-domain behavior, and injection resistance.

## Deferred complexity

Streaming may be added after the final response object is validated. The UI must not present streamed text as legally verified before the citation verifier completes.
